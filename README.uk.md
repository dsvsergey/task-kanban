# Task Kanban

[English](README.md) | **Українська**

Розширення VS Code: канбан-дошка задач для супровідних каталогів `<Name>Add` — каталогів поруч із кодом проекту,
де ведуться документація і задачі. Колонки — каталоги етапів `Tasks/<етап>/`, картки — каталоги задач
`Tasks/<етап>/<номер>/`. Перетягування картки переносить каталог задачі, оновлює рядок «Статус» у `task.md`
і запускає налаштовані дії: перевірку файлів і коміт файлів задачі.

Чистий JavaScript без залежностей і без збірки — VS Code завантажує каталог як є.

## Структура задач

```
<Name>Add/
├── .vscode/settings.json   ← налаштування дошки (taskKanban.*)
└── Tasks/
    ├── _template/          ← шаблон нової задачі (`<номер>` у файлах замінюється на номер)
    ├── 1_new/  2_queue/  3_work/  4_testing/  5_done/   ← етапи
    │   └── <номер>/
    │       ├── task.md     ← опис; рядок «- **Статус:** …» або розділ «## Статус»
    │       ├── notes.md
    │       └── …           ← артефакти: path.sql, task_<номер>.v<N>.zip, delphi/ …
```

## Встановлення на іншому комп'ютері

Розширення немає в маркетплейсі — його ставлять з файла `.vsix`. Node.js **не** потрібен.

**Потрібно:** Windows, VS Code 1.85+, Git (для комітів з дошки), PowerShell 5.1+ (є у Windows).

### 1. Отримати `.vsix`

- **З релізу** (якщо опубліковано): відкрити
  [Releases](https://github.com/dsvsergey/task-kanban/releases), завантажити `task-kanban-<версія>.vsix`
  і перейти до кроку 2.
- **Зібрати з коду:**

  ```powershell
  git clone https://github.com/dsvsergey/task-kanban.git
  cd task-kanban
  powershell -ExecutionPolicy Bypass -File .\pack.ps1   # → dist\task-kanban-<версія>.vsix
  ```

  Без Git: на GitHub **Code → Download ZIP**, розпакувати і запустити `pack.ps1` у розпакованому каталозі.

### 2. Встановити

```powershell
code --install-extension dist\task-kanban-<версія>.vsix
```

Або у VS Code: панель **Extensions** → меню `…` → **Install from VSIX…** → вибрати файл.
Потім `Developer: Reload Window`.

### 3. Налаштувати проект

1. Відкрити у VS Code каталог `<Name>Add` (у ньому має бути `Tasks/_template/`).
2. Створити каталоги етапів `Tasks/1_new` … `Tasks/5_done` (або задати свої в `taskKanban.stages`).
3. Додати `.vscode/settings.json` з `taskKanban.transitions` — див. [Переходи](#переходи); шляхи `repo`
   писати відносні (`"../my-code"`).
4. Перевірити, що git знає автора: `git config --global user.name "…"` і `git config --global user.email "…"`.
5. Натиснути **Проекти** в рядку стану.

### Оновлення і видалення

- **Оновити:** `git pull` (або завантажити новий реліз), якщо код змінювали самі — підняти `version`
  у `package.json`, перезібрати `pack.ps1` і встановити новий `.vsix` — VS Code замінить стару версію.
- **Видалити:** `code --uninstall-extension local.task-kanban` або **Uninstall** на панелі Extensions.

Що не пакується — `.vscodeignore`.

## Встановлення для розробки

**Посилання на каталог** — зміни в коді підхоплюються після `Developer: Reload Window`.

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1   # junction у ~/.vscode/extensions
powershell -ExecutionPolicy Bypass -File .\install.ps1 -Uninstall
```

Обидва способи разом не використовувати: перед `--install-extension` прибрати junction (`-Uninstall`),
інакше VS Code писатиме пакет крізь посилання прямо в каталог з кодом.

## Перенесення на інший проект або комп'ютер

- Розширення одне на VS Code; працює в будь-якій робочій області, де є `Tasks/_template`.
- Новий проект: каталоги `Tasks/_template/` і етапів (`1_new` … `5_done`) + `.vscode/settings.json` з
  `taskKanban.transitions` (приклад — нижче). Інші етапи — перевизначити `taskKanban.stages`.
- `repo` у налаштуваннях писати **відносно кореня робочої області** (`"../ultra-delphi"`), а не абсолютно —
  тоді налаштування працюють на будь-якому диску, поки `<Name>Add` і код лежать поруч.
- Settings Sync не переносить розширення не з маркетплейсу — `.vsix` ставити на кожному комп'ютері.
- Для комітів з дошки в git мають бути задані `user.name` і `user.email`.

## Проекти і дашборд

У кожного проекту своя канбан-дошка і своя структура каталогів; **дашборд** показує всі проекти і є точкою входу.

- Проекти описуються в `taskKanban.projects`: `id` (незмінний), `title`, `description`, `aliases` (інші назви
  того ж проекту в задачах), `color` (`blue`, `green`, `purple`, `orange`, `red`, `yellow` — кольори теми VS Code —
  або `#rrggbb`), а також:
  - `tasksDir` — **власний каталог задач** відносно робочої області, може бути поза нею (`../projAdd/Tasks`):
    `<tasksDir>/<етап>/<номер>/`. Усі задачі в ньому — цього проекту;
  - `stages` — **свої колонки** (як `taskKanban.stages`); без них — загальні;
  - `templateDir` — шаблон нової задачі в каталозі проекту (за замовчуванням `_template`; якщо його немає —
    загальний `Tasks/_template`);
  - `transitions` — свої дії при перенесенні (без них: проект у спільному каталозі — загальні, у власному — жодних;
    `repo` — відносно робочої області, підстановка `{tasksRoot}` — каталог задач проекту).
- Проект **без** `tasksDir` ділить спільний каталог `taskKanban.tasksDir` і загальні колонки з іншими такими
  проектами; задачі між ними розподіляє рядок `- **Проекти:** …` у `task.md` (збіг з `id`, `title` або псевдонімом
  без урахування регістру; примітки в дужках і `код` не враховуються; кома в дужках список не ділить). Назви з
  задач, яких немає в налаштуваннях, теж показуються (картка з пунктиром; ＋ — додати в налаштування). Поки спільний
  каталог нікому не належить, на дашборді є картки «Усі задачі» і «Без проекту».
- Корінь іншого проекту всередині спільного каталогу (`Tasks/<проект>/`) не вважається ні етапом, ні задачею.
- Новий проект (`+ Проект`) пропонує каталог `../<id>Add/Tasks` (якщо робоча область — `<Name>Add`) або
  `Tasks/<id>` і створює його: каталоги колонок (копія загальних) і `_template` (копія загального).

```jsonc
"taskKanban.projects": [
  // спільний каталог Tasks/ належить Ultra, колонки — загальні taskKanban.stages
  { "id": "ultra", "title": "Ultra", "tasksDir": "Tasks", "aliases": ["ultra-delphi"], "color": "blue" },
  // свій каталог поруч, свої колонки і коміти в його репозиторій
  { "id": "task-kanban", "title": "task-kanban", "color": "purple",
    "tasksDir": "../task-kanbanAdd/Tasks",
    "stages": [ { "dir": "1_new", "title": "Нове", "status": "нове" }, { "dir": "5_done", "title": "Готово", "status": "готово" } ],
    "transitions": [ { "to": "*", "actions": [ { "type": "commit", "repo": "../task-kanbanAdd",
      "paths": ["Tasks/*/{number}/**"] } ] } ] }
]
```

**Дашборд** (кнопка `Проекти` в рядку стану, `Task Kanban: Дашборд проектів`):

- підсумки: проекти, активні задачі, завершені, загальна трудомісткість (сума поля `Трудомісткість`);
- картка проекту: активні / усього / завершено, трудомісткість, розподіл задач по колонках (наведіть на сегмент —
  кількість), останні активні задачі (клік — `task.md`), час останньої зміни;
- картки «Усі задачі» і «Без проекту» (задачі без рядка «Проекти»);
- клік по картці або «Дошка →» — дошка проекту в окремій вкладці; `+ Задача` — нова задача в цьому проекті;
- `+ Проект` — назва → каталог задач → псевдоніми → опис → колір → ідентифікатор; ✎ — змінити (зміна каталогу
  задачі не переносить), ✕ — прибрати з налаштувань (задачі і каталоги лишаються); пошук за назвою, id,
  псевдонімом, описом.

«Завершені» — задачі в колонках з `"done": true` у `taskKanban.stages`; якщо таких немає — у згорнутих колонках
і в останній.

## Підзадачі

Велику задачу можна розбити на підзадачі. Підзадача — звичайна задача: свій каталог `<етап>/<номер>/`, свій
`task.md`, своя колонка, перетягується окремо. Звʼязок тримають wiki-посилання `[[номер]]` у `task.md` обох
задач — їх видно й редагувати можна просто в тексті, а в Obsidian `[[00003]]` веде на нотатку задачі:

```markdown
# Task 00003                                # Task 00003.1
- **Статус:** в роботі                      - **Статус:** нове
                                            - **Батьківська задача:** [[00003]]
## Підзадачі
- [x] [[00003.1]] Модель даних              ## Description
- [ ] [[00003.2]] Картка на дошці           Модель даних
- [ ] Документація          ← пункт плану
```

- ⊕ на картці — нова підзадача (опис → номер, пропонується `<номер>.1`, `.2`…; можна номер з трекера) або,
  якщо в розділі «Підзадачі» є пункти без посилань, **розбити за планом**: з позначених пунктів створюються
  підзадачі, а в пункти дописується `[[номер]]`. Підзадача створюється з шаблону в першій колонці того самого
  каталогу задач; рядок «Проекти» копіюється з батьківської.
- На картці батьківської — `☑ 1/3` (скільки підзадач у завершених колонках); клік розгортає список підзадач
  з їхніми колонками, клік по підзадачі — показати її картку. `☐ план 2` — пункти плану без задач.
- На картці підзадачі — `↑ 00003` (клік — показати батьківську) і смуга зліва.
- Підзадача переходить у завершену колонку (`done`) — у батьківській ставиться `[x]`, повертається — знімається.
  Батьківську з незавершеними підзадачами в завершену колонку переносить лише після підтвердження.
- `[[номер]]` у markdown-файлах каталогу задач — клікабельне посилання (Ctrl+клік) на `task.md` цієї задачі.
- Звʼязок можна задати й руками: поле `- **Батьківська задача:** [[00003]]` (або просто `00003`) у підзадачі
  чи пункт `- [ ] [[00003.1]]` у розділі батьківської — достатньо одного з двох. Якщо вони розходяться, діє поле
  підзадачі. Назви поля і розділу — `taskKanban.parentField`, `taskKanban.subtasksHeading` (розділ `Subtasks`
  розпізнається завжди).

## Використання

- Дашборд: кнопка **Проекти** в рядку стану або `Task Kanban: Дашборд проектів`. Дошка проекту — з дашборду або
  `Task Kanban: Відкрити дошку проекту`. «← Проекти» на дошці повертає на дашборд.
- ⇄ на картці — перенести задачу в інший проект: каталог задачі переїжджає в каталог задач того проекту (у ту
  саму колонку, якщо вона там є, інакше — вибрати), статус і рядок «Проекти» оновлюються.
- 🏷 на картці (лише у спільному каталозі) — вибрати проекти задачі в рядку «Проекти» (кілька; примітки в дужках
  зберігаються). Чипи *інших* проектів задачі на картці — перехід на їхні дошки.
- Колонки (◀ ▶ ✎ ＋ ✕, `+ Колонка`) на дошці проекту зі своїм каталогом змінюють його `stages` і його каталоги;
  на інших дошках — загальні `taskKanban.stages`.
- `+ Задача` створює каталог у першій колонці проекту з його шаблону і пише проект у рядок «Проекти»; на дошці
  «Усі задачі» проект питається.
- Перетягнути картку в іншу колонку — перенести задачу.
- Клік по картці — `task.md`; ✎ — `notes.md`; 📁 — показати в провіднику.
- 💬 — сесії Claude Code, у яких виконувалась задача (пошук за номером задачі у ваших запитах; ★ — сесія
  почалася з цієї задачі); вибрана відкривається в розширенні Claude Code, а без нього — у терміналі
  `claude --resume <id>` (`taskKanban.sessionOpenIn`). Те саме — команда `Task Kanban: Сесії Claude Code задачі`.
- Клік по заголовку колонки — згорнути/розгорнути.
- **Колонки** (навести на заголовок колонки): ◀ ▶ — переставити, ✎ — змінити назву і статус для `task.md`,
  ＋ — додати колонку праворуч, ✕ — видалити (лише порожню; каталог видаляється, якщо в ньому лишився тільки
  `.gitkeep`). `+ Колонка` на панелі вгорі додає колонку у вибране місце: назва → каталог (пропонується з
  назви, напр. «Архів» → `6_arkhiv`) → статус. Зміни зберігаються в `taskKanban.stages` у `.vscode/settings.json`
  проекту; доти діють стандартні п'ять колонок. `Task Kanban: Повернути стандартні колонки` прибирає
  перевизначення.
- `+ Задача` / `Task Kanban: Нова задача` — каталог із `Tasks/_template` у першому етапі.
- Жовтий бейдж «статус: …» — статус у `task.md` не збігається з етапом.
- Позначка «⏱ 3:20» — трудомісткість з рядка `- **Трудомісткість:** 3:20` у `task.md`: загальний час для
  звіту замовнику (назва поля — `taskKanban.effortField`).
- Каталоги задач просто в `Tasks/` (поза етапами) або в каталозі етапу, якого вже немає в списку колонок,
  показуються в колонці «Без етапу»; звідти їх перетягують у потрібну колонку.
- Журнал дій — панель Output → «Task Kanban».

## Налаштування

У `.vscode/settings.json` каталогу `<Name>Add`.

| Параметр | За замовчуванням | Що |
|---|---|---|
| `taskKanban.tasksDir` | `Tasks` | каталог задач |
| `taskKanban.templateDir` | `_template` | шаблон нової задачі всередині `tasksDir` |
| `taskKanban.effortField` | `Трудомісткість` | поле `task.md`, що показується на картці позначкою ⏱; порожньо — не показувати |
| `taskKanban.sessionOpenIn` | `auto` | де 💬 відкриває сесію: `auto` (розширення, інакше термінал), `extension`, `terminal` |
| `taskKanban.stages` | `1_new` … `5_done` | колонки: `dir`, `title`, `status` (значення для `task.md`), `collapsed`, `done` |
| `taskKanban.projects` | `[]` | проекти: `id`, `title`, `description`, `aliases`, `color`, `tasksDir`, `stages`, `templateDir`, `transitions` — див. [Проекти](#проекти-і-дашборд) |
| `taskKanban.projectField` | `Проекти` | поле `task.md` зі списком проектів задачі |
| `taskKanban.parentField` | `Батьківська задача` | поле `task.md` підзадачі з посиланням `[[номер]]` на батьківську |
| `taskKanban.subtasksHeading` | `Підзадачі` | розділ `task.md` зі списком підзадач і планом розбиття |
| `taskKanban.commitMessage` | `{number}` | повідомлення коміту: `{number}`, `{stage}`, `{status}`, `{title}` |
| `taskKanban.transitions` | `[]` | дії при перенесенні |

### Переходи

```jsonc
"taskKanban.transitions": [
  {
    "from": "*",               // dir етапу або *
    "to": "4_testing",
    "actions": [
      // до перенесення: попередити, якщо в каталозі задачі немає файлів за масками
      { "type": "check", "files": ["task_*.zip"] },
      // після перенесення: закомітити змінені файли задачі в репозиторій супровідного каталогу
      { "type": "commit", "name": "UltraAdd",
        "paths": ["Tasks/*/{number}/**", "Obsidian/Tasks/{number}.md"] },
      // і код: файли з Tasks/<етап>/<номер>/delphi/ шукаються в репозиторії за іменем
      { "type": "commit", "name": "ultra-delphi", "repo": "../ultra-delphi", "sourceDir": "delphi" }
    ]
  }
]
```

- `repo` — шлях до репозиторію (відносний — від кореня робочої області; за замовчуванням сама робоча область).
- `paths` — git-маски (glob) відносно кореня репозиторію; `{number}` — номер задачі.
- `sourceDir` — підкаталог задачі; кожен файл звідти шукається в репозиторії за іменем файла (без урахування
  регістру), комітяться лише змінені.
- Перед комітом показується список файлів з галочками; Esc — не комітити (перенесення лишається).
- Комітяться **лише** вибрані файли (`git commit --only`): чужі зміни, навіть проіндексовані, у коміт не потрапляють.
- Репозиторій без git — попередження і пропуск. `push` не робиться.

## Розробка

```
extension.js     — активація, панель, команди, перенесення і коміти (vscode API)
src/core.js      — логіка без vscode: сканування, статус у task.md, проекти, перенесення, git
media/board.*    — дошка у webview
media/dashboard.* — дашборд проектів у webview
test/            — тести src/core.js (node:test)
```

Налагодження: відкрити цей каталог у VS Code, `F5` (конфігурація «Run Extension») — відкриється нове вікно
з `../UltraAdd`; інший каталог — змінити `args` у `.vscode/launch.json`.

Тести (Node окремо не потрібен — використовується вбудований у VS Code):

```bash
ELECTRON_RUN_AS_NODE=1 "<каталог VS Code>/Code.exe" test/core.test.js
```

Інтеграційний тест у справжньому VS Code (окремий профіль і тимчасова робоча папка; вікно відкривається на
