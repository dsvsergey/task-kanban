# Файли задач дошки

Дошка (розширення VS Code task-kanban) не має власної бази: усе — каталоги і `task.md`. Агент працює з тими
самими файлами; дошка підхоплює зміни сама.

## Де задачі

- Налаштування — `.vscode/settings.json`, ключі `taskKanban.*`.
- Проект з `tasksDir` у `taskKanban.projects` — свій каталог задач (`Tasks/<id>/`, може бути і поза
  робочим каталогом), свої `stages` (без них — загальні `taskKanban.stages`), свій шаблон
  (`<tasksDir>/_template/`, без нього — загальний `Tasks/_template/`).
- Проект без `tasksDir` — спільний каталог `taskKanban.tasksDir` (`Tasks/<етап>/<номер>/`); проект задачі —
  рядок `- **Проекти:**`.
- Колонка: `dir` (каталог), `title` (назва), `status` (текст для `task.md`), `done` (завершена).
  **Назва і каталог можуть не збігатися** — брати з налаштувань, не вгадувати.
- Каталоги на `_` і `.` — службові, не задачі.
- **Шукати задачу за номером в усіх етапах** (`Tasks/<id>/*/<номер>/`, у спільному — `Tasks/*/<номер>/`).
  Шлях з етапом у нотатках і скриптах не зашивати: задача переїжджає.

## task.md

Файл — `task.md` (або `<щось>_task.md`). Поля — рядки списку з жирною назвою:

```markdown
# Task 00012

- **Статус:** в роботі
- **Трудомісткість:** 3:20
- **Проекти:** shop, api (лише бекенд)
- **Батьківська задача:** [[00010]]

## Description

Перші два непорожні рядки — підпис картки.

## Підзадачі
- [x] [[00012.1]] Модель даних
- [ ] [[00012.2]] Екран
- [ ] Документація        ← пункт плану без задачі
```

| Поле | Правило |
|---|---|
| `Статус` | = `status` колонки, у каталозі якої лежить задача; розбіжність — жовтий бейдж. Альтернатива — розділ `## Статус` і рядок під ним. HTML-коментарі ігноруються |
| `Трудомісткість` | `Г` або `Г:ХХ`; на картці ⏱, на дашборді сума. Інше значення (`—`) — не показується |
| `Проекти` | для спільного каталогу: через кому, збіг з `id`/`title`/`aliases`, без регістру; дужки — примітки |
| `Батьківська задача` | у підзадачі: `[[номер]]` або номер |
| `## Підзадачі` | `- [ ] [[номер]] опис`; `[x]` — підзадача в колонці з `done`. Пункти без `[[…]]` — план |

Назви полів перевизначаються (`taskKanban.effortField`, `projectField`, `parentField`, `subtasksHeading`) —
якщо задані, писати їх. Інші поля і розділи дошка не читає — їх можна додавати.
Бейджі картки: `path.sql` у каталозі задачі; `*.v<N>.zip` — «zip vN».

## Створити задачу

1. Номер — з трекера; без трекера — найбільший цифровий номер у каталозі задач проекту + 1 з тими ж
   провідними нулями (`00006` → `00007`). Символи: літери, цифри, `.`, `_`, `-`. Перевірити, що номера немає
   в жодній колонці.
2. Скопіювати шаблон проекту в **першу** колонку: `<tasksDir>/<перший dir>/<номер>/`.
3. У `.md`, `.txt`, `.sql` замінити `<номер>` на номер; `Статус` — status першої колонки; `Проекти` — id проекту;
   опис — у `## Description` (з трекера — дослівно).

## Перенести між колонками

Лише за вказівкою користувача або за правилом колонок агента (`kanban-workflow`).

1. Перенести каталог `<tasksDir>/<звідки>/<номер>/` → `<tasksDir>/<куди>/<номер>/` (`git mv`, якщо під git).
2. `Статус` у `task.md` — status нової колонки.
3. Підзадача прийшла в колонку з `done` — `[x]` у пункті батьківської; пішла — зняти.

Ручне перенесення **не** виконує `transitions` (перевірки `check`, коміти `commit`). Якщо для цієї колонки є
переходи — сказати користувачу (коміт зробити самому або перетягнути картку на дошці).

## Підзадачі

- Підзадача — звичайна задача з номером `<батьківська>.1`, `.2`… у першій колонці того самого каталогу, з
  полем `Батьківська задача: [[<номер>]]` і тим самим рядком `Проекти`.
- У батьківській у `## Підзадачі` — `- [ ] [[<номер підзадачі>]] <опис>` (або дописати `[[…]]` у пункт плану).
- План без задач (пункти без `[[…]]`) — користувач може розбити кнопкою ⊕ на картці.

## Сесії агента

Кнопка 💬 на картці шукає сесії Claude Code, у запитах яких є номер задачі (від 4 цифр), — номер задачі варто
називати в першому запиті сесії.
