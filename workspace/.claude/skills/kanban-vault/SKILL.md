# Obsidian-vault проектів

Vault — `Obsidian/` (відкривати в Obsidian як vault саме цей каталог). Це памʼять між сесіями: агент планує
наступні задачі за нею, тож вона має бути точною, короткою і звʼязаною посиланнями.

## Структура

```
Obsidian/
├── 00 Index.md                  ← вхід: список проектів, спільні знання
├── Templates/                   ← Project, Rules, Module, Flow, Data, Decision, Task
├── <id>/                        ← розділ проекту (id = settings.yaml → projects[].id)
│   ├── <id>.md                  ← огляд: що це, код, стек, архітектура, списки нотаток (MOC)
│   ├── Правила (<id>).md        ← особливості для агента; пріоритет над AGENTS.md
│   ├── Modules/                 ← модуль, пакет, клас, форма, сервіс
│   ├── Flows/                   ← наскрізний сценарій (від дії до результату)
│   ├── Data/                    ← таблиця, колекція, формат файла, зовнішній API
│   ├── Decisions/               ← рішення: YYYY-MM-DD <суть>.md
│   └── Tasks/                   ← підсумки задач: <id>-<номер>.md
└── Shared/                      ← спільне для кількох проектів (інфраструктура, бібліотеки)
```

## Імена і посилання

- Одна нотатка — одна сутність; ім'я = ім'я сутності (`OrderService`, `Оформлення замовлення`, `orders`).
- **Імена унікальні в усьому vault** (посилання `[[Ім'я]]` — без шляху). Збіг з іншим проектом — суфікс
  ` (<id>)`: `core.js (shop)`. Тому правила — `Правила (<id>)`, підсумки задач — `<id>-<номер>`.
- Посилання: `[[Нотатка]]`, з іншим текстом — `[[Нотатка|текст]]`. Код — шлях від каталогу репозиторію з
  рядком: `` `shop-api/app/orders.py:120` `` (рядки зсуваються — головне ім'я функції/класу).
- Не посилатися на каталог задачі з етапом: `Tasks/<id>/*/<номер>/`.

## Frontmatter

Кожна нотатка — з frontmatter із шаблону: `type` (project, rules, module, flow, data, decision, task, index),
`project` (id; кілька — списком), `tags`, `updated` (YYYY-MM-DD). У задачі — `task`, `status`, `effort`;
у рішенні — `date`, `status` (прийнято / замінено [[…]]), `task`.

Шаблони мають змінні Obsidian `{{title}}`, `{{date}}` — створюючи нотатку без Obsidian, підставити значення
самому, а `<проект>`, `<номер>` — замінити.

## Після задачі (обовʼязково)

1. **Знання** — оновити або створити нотатки `Modules/`, `Flows/`, `Data/` про те, що зʼясовано або змінено:
   призначення, ключові функції з місцем у коді, нюанси й пастки. Наявну нотатку — оновити (і `updated`),
   а не створювати другу. Застаріле — виправити або прибрати.
2. **Рішення** — кожне погоджене рішення — `Decisions/YYYY-MM-DD <суть>.md` (контекст, рішення, альтернативи,
   наслідки). Замінене рішення — `status: замінено [[нове]]`, не видаляти.
3. **Підсумок задачі** — `Tasks/<id>-<номер>.md` за шаблоном Task: що зроблено, `[[посилання]]` на знання з
   пп. 1–2, що лишилось, `effort`.
4. **Огляд проекту** `<id>.md` — нові нотатки в його списки, задача — рядком у «Задачі» (нові зверху).
5. **Індекс** `00 Index.md` — лише якщо зʼявився новий проект або спільна нотатка.
6. У `task.md → ## Знання` — `[[посилання]]` на створене й оновлене.

Що не варто переносити у vault: хід пошуку, хибні гіпотези, логи — вони лишаються в `notes.md` задачі.

## Перед плануванням (читання)

`00 Index.md` → `<id>.md` → `Правила (<id>)` → `Decisions/` (чинні) → нотатки за темою задачі → підсумки
схожих задач (`Tasks/`, пошук за словами опису). Знайдене — коротко в `notes.md → Контекст`.
Якщо нотатка розходиться з кодом — правда в коді; нотатку виправити в цій же задачі.

## Новий проект у vault

Створити `<id>/<id>.md` (шаблон Project) і `<id>/Правила (<id>).md` (шаблон Rules), рядок у
`00 Index.md → Проекти`. Перше дослідження коду — короткий огляд архітектури і нотатки 3–5 головних модулів;
решта — по мірі задач.
